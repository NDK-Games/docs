# Правила самостоятельной работы

> Архив предыдущей редакции, только для игр. Этот файл сохраняет процесс из трёх этапов и не является действующим шаблоном. Для новых постановок используется [игровой регламент из 17 этапов](../../../GAME_LIFECYCLE.md); [об архиве](../README.md).

Статус: [черновик / согласовано]. Эти правила входят в будущую постановку после явного принятия владельцем.

## Кто принимает решения

Владелец определяет продукт, аудиторию, бюджет, бизнес-модель, разрешённые внешние действия и существенное изменение объёма. Он проверяет результат каждого из трёх этапов и явно подтверждает продолжение. Агент разрабатывает и выполняет технические решения, детали подачи, рабочую очередь, исправления и проверки внутри разрешённого этапа.

При противоречии сначала учитывать последнее явное решение владельца с учётом обязательных правил среды и платформы. Документы привести к этому решению. Не подбирать юридически значимые или финансовые сведения по предположению.

## Подтверждение этапов

1. После документации передать ссылки, редакции и вопросы; остановиться до подтверждения этапа 2.
2. После создания проекта передать сборки, инструкции, демонстрацию и отчёт проверок; остановиться до подтверждения этапа 3.
3. После оформления страниц передать ссылки и предпросмотры обоих магазинов; остановиться до принятия результата пользователем.

Для каждой проверки записать предъявленную версию, ответ пользователя и дату. Пример явного перехода: «Документы утверждаю, переходи к созданию проекта». Молчание, истечение времени, успешные тесты и замечания без разрешения перехода не являются подтверждением. Если пользователь прислал замечания, доработать текущий этап и представить результат повторно.

## Самостоятельное исполнение

Внутри разрешённого этапа агент выбирает следующую задачу по зависимостям, выполняет её, проверяет результат, обновляет план и продолжает без отдельного поручения на каждый экран и тест. На границе этапа передаёт проверяемый результат, устанавливает статус «Ожидает проверки пользователя» и прекращает переход к следующим работам. Не расширяет продукт за счёт всех встреченных идей.

Существующие данные владельца сохраняются. Чистые, аварийные и платёжные сценарии выполняются на тестовых профилях. Секреты не попадают в переписку, исходники, изображения и журналы. Внешние действия выполняются только в пределах выбранных полномочий.

## Блокеры и отчётность

Запрос к владельцу содержит конкретное недостающее решение или действие, подготовленный материал и то, что зависит от ответа. При внешней зависимости продолжаются только независимые задачи текущего разрешённого этапа. На обязательной остановке работы следующего этапа не начинаются. При ожидании внешней системы сохраняются её статус и следующий шаг; завершение не объявляется преждевременно.

Обновления сообщают достигнутый результат, оставшуюся неопределённость и ближайшую проверку. Передача незавершённой работы содержит актуальную очередь, состояние файлов и внешние зависимости.
