# Пример правил работы над Садом на крыше

> Архив предыдущей редакции, только для игр. Этот файл сохраняет процесс из трёх этапов и не является действующим шаблоном. Для новых постановок используется [игровой регламент из 17 этапов](../../../GAME_LIFECYCLE.md); [об архиве](../README.md).

Учебный вариант полномочий для будущей цели. Для применения владелец должен включить эти правила в свою постановку. В текущем чате никаких внешних действий они не разрешают.

## Самостоятельные решения агента

Агент выбирает архитектуру, структуру кода, детали интерфейса, игровые ассеты, реализации механик, рабочую очередь и проверки внутри разрешённого этапа. Уточняет веса выдачи и рецепты заказов внутри описанного объёма, исправляет дефекты и обновляет документацию. Переход между тремя этапами требует явного подтверждения пользователя.

Решения о дополнительных зонах, новых платформах, изменении аудитории, бизнес-модели, стране выпуска и реальных расходах остаются за владельцем. Количество обязательного контента не уменьшается для формального закрытия цели.

## Пример выбранных полномочий

| Действие | Разрешение в учебной постановке |
| --- | --- |
| Подготовка документации | Этап 1; после подготовки остановиться для проверки пользователя |
| Изменение проекта и тестовых данных | Этап 2 после принятия документов; пользовательские данные сохраняются |
| Сборка и тесты | Внутри разрешённого этапа 2 в изолированных профилях |
| Тестовые покупки | На этапе 2 только официальными средствами без реальных списаний |
| Служебная настройка и тестовые каналы | На этапе 2 в согласованном объёме для SDK и проверки сборок |
| Страницы Google Play и App Store | На этапе 3 после принятия проекта; сохранить черновики и передать на ревью |
| Модерация и публичный выпуск | Только по отдельному явному поручению после проверки страниц; автоматически не разрешены |
| Платные материалы и сервисы | Не разрешены; внешний бюджет 0 |
| Новые договоры, юридические, банковские и налоговые изменения | Владелец принимает решение и выполняет требуемое подтверждение |
| Сообщения другим людям | Требуется отдельное явное поручение |

## Пример начального реестра решений

| ID | Вопрос | Решение примера | Состояние |
| --- | --- | --- | --- |
| D01 | Платформы и результат | Android/iOS, принятый проект и черновики Google Play/App Store | Выбрано для примера |
| D02 | Аудитория и страна | 18+, США | Выбрано для примера; документы должны соответствовать |
| D03 | Монетизация | Один IAP и добровольное видео; без принудительных показов | Выбрано для примера |
| D04 | Внешние расходы | 0; любые платежи согласуются отдельно | Выбрано для примера |
| D05 | Идентификаторы, подпись, юридические данные | Требуются реальные данные владельца | Внешняя зависимость до соответствующих этапов |
| D06 | Участники и устройства | Три новых участника и устройства Android/iOS предоставляет владелец | Внешняя зависимость приёмки |
| D07 | Проверки пользователя | Остановка после документации, проекта и оформления двух страниц | Обязательны; подтверждения ещё не получены |

Реестр показывает разницу между выбранной моделью и ещё не полученными ресурсами. Агент не выдумывает юридические сведения, не имитирует людей и не отмечает проверки на отсутствующем устройстве как выполненные.

## Обязательные остановки

После этапа 1 передать редакции документов и ждать проверки и явного разрешения создавать проект. После этапа 2 передать сборки, инструкции и QA-отчёт и ждать тестирования и явного разрешения оформлять магазины. После этапа 3 передать страницы обоих магазинов с предпросмотрами и ждать принятия пользователем.

На каждой границе установить статус «Ожидает проверки пользователя» и не выполнять следующие работы. Подтверждение фиксируется с датой и предъявленной версией. Замечания исправляются в текущем этапе, затем результат предъявляется повторно. Молчание, время и успешные тесты не считаются подтверждением. Принятие страниц само по себе не разрешает их отправку на модерацию или публичный выпуск.

## Блокеры и продолжение

Если нет доступа к кабинетам, агент выполняет доступные задачи текущего разрешённого этапа. Если на этапе 2 нет участников, готовит сценарии и исправляет технические дефекты. Внешняя зависимость не разрешает начинать следующий этап. Запрос к владельцу содержит конкретное действие и объяснение зависимости.

Агент хранит текущий этап, статус, подтверждения, версии, результаты и следующий разрешённый шаг. После перерыва проверяет эти записи и не отменяет ожидание пользователя автоматически. Цель закрывается только после явного принятия пользователем результата этапа 3 для обоих магазинов и выполнения предыдущих проверок.
