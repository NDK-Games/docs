# Профили проектов

Общие разделы `00-context/`–`06-history/` используются для всех проектов. Эта папка содержит дополнения, зависящие от типа продукта: жизненный цикл, специальные шаблоны и примеры. Подключение профиля не создаёт вторую систему планирования.

## Выбор процесса

| Тип проекта | Процесс | Состояние |
| --- | --- | --- |
| Мобильная игра (`game`) | [Игровой профиль](games/README.md): 17 этапов разработки и развития | Готов к использованию; проверка пользователя после каждого этапа |
| Сервис (`service`) | [Существующий регламент сервиса](../02-team/process/SERVICE_LIFECYCLE_REGULATION.md): 18 этапов | Сохранён; применяется при явном выборе для сервиса |
| Веб-проект, приложение другого типа, иной продукт | Отдельный профиль будет добавлен позднее | Специальный процесс пока не описан; игровой не подставляется автоматически |

Для веб-проекта можно явно выбрать существующий процесс сервиса, если он подходит задаче. Это не заменяет будущий отдельный веб-профиль.

## Как подключить профиль

1. В [PROJECT.md](../01-product/strategy/PROJECT.md) записать тип продукта и ссылку на **один основной** регламент жизненного цикла. Для игры выбрать `games/GAME_LIFECYCLE.md`.
2. Там же зафиксировать единую цель, границы, полномочия, платформы и критерий завершения. Если часть решений ещё не принята, обозначить её как вопрос, а не как свершившийся факт.
3. В [STATE.md](../01-product/strategy/STATE.md) создать реестр этапов выбранного процесса. Это единственный рабочий реестр статусов и решений о переходах.
4. Вести вехи в [ROADMAP.md](../01-product/strategy/ROADMAP.md), задачи текущего спринта — в [PLAN.md](../01-product/planning/PLAN.md), будущие задачи — в [BACKLOG.md](../01-product/planning/BACKLOG.md).
5. Применять общие [workflow](../02-team/process/WORKFLOW.md), [спринты](../02-team/process/SPRINT_REGULATION.md) и [review](../02-team/process/REVIEW_POLICY.md) внутри разрешённых границ выбранного процесса.

**Для игры переход между этапами разрешает пользователь.** Техническое review, решение CEO Agent, закрытый спринт, доступ к кабинету или наступление срока не заменяют его подтверждение. До подтверждения доступны доработки текущего этапа; работы следующего не начинаются. Подробные условия принадлежат [игровому регламенту](games/GAME_LIFECYCLE.md).

Наличие шаблонов в этом репозитории само по себе не запускает проект и не предоставляет доступов или полномочий на публикацию и расходы.

## Как добавить следующий профиль

Для нового типа создать отдельную папку, например `web/`, когда его процесс будет разработан. В неё включить:

- `README.md`: область применения и способ подключения;
- регламент жизненного цикла: этапы, результаты, критерии и правила переходов;
- `templates/`: только специальные формы, которых нет в общем ядре;
- `examples/`: учебные примеры с явной пометкой;
- карту размещения фактов в общей структуре документации.

После этого обновить этот каталог и [карту документации](../00-context/DOCS.md). Не переносить правила магазинов, игровых механик или AdMob в обязательные требования других типов проектов. Если профиль не выбран, сначала согласовать процесс, а не смешивать несколько нумераций этапов.
