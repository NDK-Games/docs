# Analytics Report Template

Этот шаблон заполняет Analyst Agent. Пользователь не должен заполнять его вручную.

Шаблон используется для ежедневного отчета, недельного summary, анализа релиза, аномалии или A/B-теста. Неприменимые разделы помечаются `не применимо`.

## Комплект артефактов

Каждый выпуск отчета состоит из трех файлов, построенных по одному периоду и одному набору данных:

| Артефакт | Формат | Назначение | Обязательные свойства |
| --- | --- | --- | --- |
| Интерактивный отчет | `.html` | Исследование показателей и разрезов | Интерактивные графики, таблицы, фильтры и понятные подсказки; файл открывается локально без отдельного сервера |
| Текстовый отчет | `.md` | Полный вывод, ограничения, рекомендации и handoff | Читается без HTML, содержит ссылки на источники и все рекомендации |
| Snapshot отчета | `.json` | Машиночитаемое состояние отчета для автоматизации, сравнения и повторного использования | Валидный JSON с метаданными, показателями, воронками, сегментами, аномалиями и рекомендациями |

Имена файлов формируются единообразно:

```text
analytics_<type>_<period>.html
analytics_<type>_<period>.md
analytics_<type>_<period>_snapshot.json
```

Все три файла должны содержать одинаковые период, часовой пояс, время формирования и статус данных. Markdown является полным текстовым отчетом, HTML — его интерактивным представлением, snapshot — машиночитаемым состоянием данных и выводов. Если артефакты расходятся, выпуск считается незавершенным.

Snapshot должен быть валидным UTF-8 JSON без комментариев, `NaN` и `Infinity`. Верхний уровень содержит как минимум: `schema_version`, `report_id`, `report_type`, `period`, `generated_at`, `timezone`, `data_status`, `sources`, `metrics`, `funnels`, `behavior`, `purchases_subscriptions`, `advertising`, `errors`, `experiments`, `reviews`, `anomalies`, `recommendations` и `limitations`. Объект `recommendations` разделяется на ключи `quality`, `metrics`, `funnels`, `behavior`, `purchases_subscriptions`, `advertising`, `errors`, `experiments`, `reviews` и `anomalies`. Числовые значения сохраняются числами, а не форматированными строками; отсутствующие значения передаются как `null` с пояснением в `limitations`.
