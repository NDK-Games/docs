# COMMANDS

## Назначение

Этот документ хранит быстрые команды проекта: установка, локальный запуск, проверки, сборка, деплой, rollback, обновление и диагностика.

Цель документа - дать участнику проекта один короткий вход для выполнения типовых действий без поиска по разным файлам.

## Правило владения

`COMMANDS.md` является source of truth для готовых команд, которые можно выполнить вручную.

Если команда вызывает проектный скрипт, подробное описание самого скрипта хранится в [`SCRIPTS.md`](SCRIPTS.md). Здесь нужно оставить только команду запуска, назначение и момент применения.

Профильные документы могут дублировать релевантные команды рядом со своим процессом, чтобы читателю не приходилось переходить между файлами. Такие локальные копии должны совпадать с одноименными строками из этого документа.

Если команда меняется, в одной правке нужно обновить:

- строку в этом документе;
- все локальные копии команды в профильных документах;
- описание связанного скрипта в [`SCRIPTS.md`](SCRIPTS.md), если команда вызывает скрипт.

## Перед выполнением

- Проверить нужное окружение в [`ENVIRONMENT.md`](ENVIRONMENT.md).
- Проверить доступы и секреты в [`SECURITY.md`](SECURITY.md), если команда затрагивает staging или production.
- Перед production-деплоем пройти [`RELEASE_CHECKLIST.md`](RELEASE_CHECKLIST.md).
- После изменения команды обновить все локальные копии в профильных документах.

## Как добавлять команду

1. Указать точную команду, которую можно скопировать и выполнить.
2. Указать назначение без пересказа реализации.
3. Указать момент применения и ссылку на профильный документ.
4. Если команда опасная, добавить ограничение в колонку "Когда использовать" или профильный runbook.
5. Если команда дублируется в профильном документе, скопировать ее туда без изменений.
